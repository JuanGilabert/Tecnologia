# ✅ Principios y buenas prácticas

ESTE README DE NIVEL 2 CONTENDRA BREVES DESCRIPCIONES E IMAGENES.
ENLAZARA CON LOS README DE NIVEL 3 LOS CUALES DETALLARAN CON EXACTITUD LAS TECNOLOGIAS.

Los principios y las buenas prácticas orientan el desarrollo hacia un código más legible, coherente, mantenible y adaptable a los cambios.

- [**Clean Code**](principios-y-buenas-practicas/clean-code/README.md): promueve un código claro, expresivo y fácil de comprender, probar y modificar.
![Clean Code](principios-y-buenas-practicas/clean-code/imagenes/clean-code_example.png)
- [**SOLID**](principios-y-buenas-practicas/solid/README.md): reúne cinco principios de diseño orientado a objetos que favorecen la cohesión, la extensibilidad y un acoplamiento reducido.
![SOLID](principios-y-buenas-practicas/solid/solid_example.png)
- [**DRY (Don't Repeat Yourself)**](principios-y-buenas-practicas/dry/README.md): evita duplicar conocimiento o reglas de negocio en distintos lugares del sistema.
![DRY](principios-y-buenas-practicas/dry/dry_example.png)
- [**KISS (Keep It Simple, Stupid)**](principios-y-buenas-practicas/kiss/README.md): favorece soluciones sencillas y comprensibles frente a una complejidad innecesaria.
![KISS](principios-y-buenas-practicas/kiss/kiss_example.png)
- [**YAGNI (You Aren't Gonna Need It)**](principios-y-buenas-practicas/yagni/README.md): evita implementar funcionalidades anticipadamente cuando no existe una necesidad concreta que las justifique.
![YAGNI](principios-y-buenas-practicas/yagni/yagni_example.png)

Estos principios deben aplicarse con criterio y según el contexto: no constituyen reglas absolutas ni sustituyen el análisis de los requisitos del sistema.
